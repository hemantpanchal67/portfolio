1. What are VPC Endpoints?

A VPC endpoint lets resources in your VPC reach AWS services and other VPCs' services privately, over the AWS network, without an Internet Gateway, NAT device, VPN or public IP addresses. The traffic never crosses the public internet, which improves security and often reduces cost.

Without endpoints, a private instance that calls S3 or Secrets Manager must go out through a NAT Gateway and the internet path. With an endpoint, the call stays on the AWS backbone and reaches the service through a private IP or a route-table entry. There are several types, which the next lesson explains.

Features and benefits

Endpoints give you private connectivity, lower NAT costs, simple compliance stories ("no internet access"), policy control over what can pass, and they scale automatically.

Problems and limits

Interface endpoints cost per hour per AZ plus per GB, so many endpoints add up. Gateway endpoints work only for S3 and DynamoDB and cannot be reached from on-premises or across peered VPCs. DNS misconfiguration is a frequent source of confusion, and endpoint policies and bucket policies can accidentally lock people out.

aws ec2 create-vpc-endpoint --vpc-id vpc-123 --service-name com.amazonaws.us-east-1.s3 --route-table-ids rtb-a rtb-b
aws ec2 create-vpc-endpoint --vpc-id vpc-123 --vpc-endpoint-type Interface \
  --service-name com.amazonaws.us-east-1.secretsmanager --subnet-ids subnet-a subnet-b \
  --security-group-ids sg-123 --private-dns-enabled

2. Gateway vs Interface Endpoints in Detail

A gateway endpoint is a target in your route table. When you create one for S3 or DynamoDB, AWS adds a route for the service prefix list that points to the endpoint, and because it is more specific than 0.0.0.0/0, traffic to those services bypasses the NAT. It is free, has no security group, and works only inside the VPC.

An interface endpoint creates elastic network interfaces with private IPs in your subnets, powered by AWS PrivateLink. It supports a large set of services (and partner and your own services), has a security group, and can be reached from peered VPCs, Transit Gateway, VPN and Direct Connect. It costs per AZ per hour plus data processing.

resource "aws_vpc_endpoint" "s3" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.${var.region}.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = [for rt in aws_route_table.private : rt.id]
}
resource "aws_vpc_endpoint" "ecr" {
  vpc_id              = aws_vpc.main.id
  service_name        = "com.amazonaws.${var.region}.ecr.dkr"
  vpc_endpoint_type   = "Interface"
  subnet_ids          = aws_subnet.private[*].id
  security_group_ids  = [aws_security_group.endpoints.id]
  private_dns_enabled = true
}

3. DNS, Routing and Hybrid Access

With private DNS enabled, the normal service hostname such as secretsmanager.us-east-1.amazonaws.com resolves to the endpoint's private IPs inside the VPC, so applications need no code change. This requires DNS support and DNS hostnames to be enabled on the VPC. Each interface endpoint also gets regional and zonal DNS names you can use directly.

For gateway endpoints, routing, not DNS, does the work: the prefix-list route wins by longest prefix match. For on-premises clients, resolve the endpoint names with Route 53 Resolver inbound endpoints and connect over VPN or Direct Connect. Place interface endpoint ENIs in every AZ you use, so traffic stays local and survives an AZ outage.

aws ec2 modify-vpc-attribute --vpc-id vpc-123 --enable-dns-support
aws ec2 modify-vpc-attribute --vpc-id vpc-123 --enable-dns-hostnames
nslookup secretsmanager.us-east-1.amazonaws.com        # should return private 10.x addresses
aws ec2 describe-prefix-lists --filters Name=prefix-list-name,Values=com.amazonaws.us-east-1.s3

4. Securing Endpoints and PrivateLink

Security has several layers. An endpoint policy is an IAM-style policy attached to the endpoint that limits which principals, actions and resources can pass through it. The security group on an interface endpoint should allow HTTPS (443) only from the clients that need it. Bucket policies can require that requests come through your endpoint with the aws:SourceVpce condition, which keeps sensitive data reachable only from your VPC. All of these combine with normal IAM identity policies.

{ "Version": "2012-10-17", "Statement": [ {
  "Sid": "OnlyThroughMyEndpoint", "Effect": "Deny", "Principal": "*",
  "Action": "s3:*", "Resource": ["arn:aws:s3:::my-data", "arn:aws:s3:::my-data/*"],
  "Condition": { "StringNotEquals": { "aws:SourceVpce": "vpce-0abc123" } } } ] }

PrivateLink for your own service: put your service behind a Network Load Balancer, create an endpoint service, and let consumers in other VPCs or accounts create interface endpoints to it. Unlike VPC peering, it exposes only that service, is one-way, and works even when CIDR ranges overlap, which is why SaaS vendors love it.

Test an S3 deny-unless-endpoint policy carefully, because it also blocks console and admin access from outside the VPC.

5. Cost, Design Patterns & Troubleshooting

The main financial reason to use endpoints is to keep AWS-service traffic off the NAT Gateway; the S3 gateway endpoint alone often saves a lot. But interface endpoints are billed per AZ per hour, so add only the ones you need (commonly ECR, CloudWatch Logs, Secrets Manager, SSM, STS) and consider centralising them in a shared VPC when you have many accounts.

Troubleshooting

Work through DNS (does the name resolve to private IPs?), the security group and endpoint policy, route table association for gateway endpoints, and finally bucket or IAM policies that may deny the request.

6. Interview Q&A: VPC Endpoints

Q1. What is a VPC endpoint?

Short answer: A private connection from your VPC to AWS services or endpoint services without using the internet, NAT or VPN.

Traffic stays on the AWS network.

Q2. Gateway versus interface endpoint?

Short answer: Gateway endpoints are route-table targets for S3 and DynamoDB and are free; interface endpoints are ENIs powered by PrivateLink for many services and are charged.

Only interface endpoints support security groups and on-premises access.

Q3. Which services support gateway endpoints?

Short answer: Amazon S3 and Amazon DynamoDB only.

Use interface endpoints for the rest.

Q4. What is AWS PrivateLink?

Short answer: Technology that exposes a service privately to consumer VPCs via interface endpoints, without peering or internet.

It uses an NLB behind an endpoint service.

Q5. How does a gateway endpoint steer traffic?

Short answer: It adds a prefix-list route to chosen route tables, which wins by longest prefix match.

No DNS change needed.

Q6. What is private DNS?

Short answer: A setting that makes the public service hostname resolve to the endpoint's private IPs inside the VPC.

Needs DNS support and hostnames enabled.

Q7. Can on-premises use a gateway endpoint?

Short answer: No, gateway endpoints work only from within the VPC.

Use an interface endpoint with VPN or Direct Connect.

Q8. How do you reduce NAT cost with endpoints?

Short answer: Route S3 and DynamoDB via free gateway endpoints and heavy AWS API traffic via interface endpoints.

Check flow logs first.

Q9. What is an endpoint policy?

Short answer: A resource policy on the endpoint limiting the principals, actions and resources allowed through it.

Default is full access.

Q10. How do you restrict an S3 bucket to your VPC?

Short answer: A bucket policy denying requests unless aws:SourceVpce or aws:SourceVpc matches.

Keep an admin exception.

Q11. Why deploy interface endpoints in every AZ?

Short answer: For AZ resilience and to avoid cross-AZ data charges.

Each AZ gets its own ENI.

Q12. Which endpoints does Systems Manager need without internet?

Short answer: ssm, ssmmessages and ec2messages (plus others for extra features).

Use private DNS.

Q13. How do private ECS or EKS tasks pull ECR images?

Short answer: With ecr.api and ecr.dkr interface endpoints plus an S3 gateway endpoint for image layers.

Also logs endpoints if needed.

Q14. PrivateLink versus VPC peering?

Short answer: PrivateLink exposes one service, is one-way, supports overlapping CIDRs; peering connects whole networks and needs non-overlapping CIDRs.

Use PrivateLink for service exposure.

Q15. How do you expose your own service via PrivateLink?

Short answer: Put it behind a Network Load Balancer, create an endpoint service and let consumers create interface endpoints.

You can require approval.

Q16. What does a Gateway Load Balancer endpoint do?

Short answer: Routes traffic to appliance fleets for transparent inspection.

Used for firewalls and IPS.

Q17. What are endpoint costs?

Short answer: Gateway endpoints are free; interface endpoints cost per AZ per hour plus per GB processed.

Remove unused ones.

Q18. Service still resolves to a public IP. Why?

Short answer: Private DNS is disabled or the VPC lacks DNS support or hostnames.

Fix settings and retest.

Q19. How do spokes share endpoints?

Short answer: Centralise interface endpoints in a hub VPC reachable through Transit Gateway and share private hosted zones.

It saves duplicates but adds complexity.

Q20. Connected but AccessDenied. Why?

Short answer: An endpoint, bucket or IAM policy is denying the call.

Review all of them.
