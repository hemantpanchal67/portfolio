1. What is EC2 and its Lifecycle?

Amazon EC2 (Elastic Compute Cloud) provides resizable virtual servers called instances. You choose the operating system image (AMI), the hardware shape (instance type), storage, networking and security, and AWS runs it on its Nitro virtualisation platform within seconds. You pay for what you use and can scale up or down at will.

An instance moves through a lifecycle. It starts in pending, becomes running and is billed, and can then be stopped (compute billing stops, EBS volumes remain), hibernated (memory saved to the encrypted root volume) or terminated (deleted). A stop and start may place it on different hardware, so the auto-assigned public IP changes and instance store data is lost.

Features and benefits

EC2 offers a huge choice of instance types, flexible pricing models, tight integration with VPC, EBS, ELB and Auto Scaling, full control of the OS, and global availability across Regions and AZs.

Problems and limits

You are responsible for patching, hardening and monitoring the OS. A single instance is a single point of failure in one AZ, unused instances waste money, on-demand prices are the highest, and capacity for some types can be limited in a given AZ. For many workloads, containers or serverless remove that operational burden.

aws ec2 run-instances --image-id ami-0abc --instance-type t3.micro --subnet-id subnet-123 \
  --security-group-ids sg-123 --iam-instance-profile Name=app-role --key-name mykey \
  --metadata-options HttpTokens=required --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=web1}]'
aws ec2 stop-instances --instance-ids i-123
aws ec2 describe-instances --query "Reservations[].Instances[].[InstanceId,State.Name,InstanceType]" --output table

2. Instance Types and Families

An instance type name like m7g.xlarge encodes the family (m), generation (7), extra attributes (g means Graviton ARM, a means AMD, i means Intel, d means local disks, n means more networking) and size (xlarge). Families fit workloads: general purpose (M, T), compute optimised (C), memory optimised (R, X), storage optimised (I, D) and accelerated (P, G, Inf, Trn).

T family instances are burstable: they earn CPU credits while idle and spend them when busy, which is cheap for light workloads but throttles under sustained load (or costs extra in unlimited mode). Graviton instances often give better price-performance, if your software supports ARM. Always right-size using CloudWatch and Compute Optimizer.

3. Purchasing Options and Cost

On-Demand is pay-per-second flexibility with the highest price. Savings Plans and Reserved Instances trade a one- or three-year commitment for large discounts, and Compute Savings Plans are the most flexible. Spot uses spare capacity at deep discounts, but AWS can reclaim it with a two-minute warning, so it suits stateless, fault-tolerant work. Dedicated Hosts give physical servers for licensing and compliance, and Capacity Reservations guarantee capacity in an AZ.

resource "aws_autoscaling_group" "web" {
  min_size = 2  max_size = 10  vpc_zone_identifier = aws_subnet.private[*].id
  mixed_instances_policy {
    instances_distribution { on_demand_base_capacity = 2  on_demand_percentage_above_base_capacity = 20  spot_allocation_strategy = "price-capacity-optimized" }
    launch_template { launch_template_specification { launch_template_id = aws_launch_template.web.id  version = "$Latest" }
      override { instance_type = "m7g.large" } override { instance_type = "m6g.large" } override { instance_type = "c7g.large" } }
  }
}

Other cost levers: stop dev instances at night, delete unused volumes and Elastic IPs, use Graviton, and review with Cost Explorer and Compute Optimizer.

4. Networking, Access and Security

Each instance has one or more elastic network interfaces carrying private IPs, optional Elastic IPs and security groups. Control inbound access with security groups, give AWS permissions through an IAM role in an instance profile (never stored keys), and reach the box with Systems Manager Session Manager instead of open SSH. The instance metadata service at 169.254.169.254 hands out role credentials, so require IMDSv2, which uses session tokens and defeats most SSRF attacks.

aws ec2 modify-instance-metadata-options --instance-id i-123 --http-tokens required --http-put-response-hop-limit 1
TOKEN=$(curl -sX PUT http://169.254.169.254/latest/api/token -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
curl -sH "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/iam/security-credentials/
aws ssm start-session --target i-123
Keep application servers in private subnets and expose only a load balancer. Patch with Systems Manager Patch Manager and monitor with CloudWatch agent and Inspector.

5. Auto Scaling, Placement and Launch Templates

An Auto Scaling group keeps a desired number of instances across AZs, replaces unhealthy ones, and scales with policies such as target tracking (keep CPU near 50%) or schedules. It launches instances from a launch template, a versioned definition of AMI, type, networking, role and user data. Placement groups shape where instances run: cluster for low latency, spread for a few critical instances on separate hardware, and partition for large distributed systems.

resource "aws_launch_template" "web" {
  name_prefix   = "web-"
  image_id      = data.aws_ssm_parameter.al2023.value
  instance_type = "t3.small"
  iam_instance_profile { name = aws_iam_instance_profile.web.name }
  metadata_options { http_tokens = "required" }
  user_data = base64encode(file("boot.sh"))
}
resource "aws_autoscaling_policy" "cpu" {
  name = "cpu50" autoscaling_group_name = aws_autoscaling_group.web.name policy_type = "TargetTrackingScaling"
  target_tracking_configuration { target_value = 50 predefined_metric_specification { predefined_metric_type = "ASGAverageCPUUtilization" } }
}

For quick boots, bake an AMI with dependencies instead of installing everything in user data, and drain connections with lifecycle hooks.

7. Interview Q&A: EC2

Q1. What is EC2?

Short answer: A service providing resizable virtual servers (instances) in the AWS cloud on the Nitro platform.

You control OS, networking and storage.

Q2. Describe the instance lifecycle.

Short answer: Pending, running, stopping, stopped, hibernated, shutting-down and terminated.

Billing runs while running.

Q3. What happens to data on stop versus terminate?

Short answer: On stop, EBS data and private IP persist while instance store is lost; on terminate the instance is deleted and root volumes are removed by default.

Check DeleteOnTermination.

Q4. What is an AMI?

Short answer: A template containing the OS, software and block device mappings used to launch instances.

See the AMI course.

Q5. What are the instance families?

Short answer: General purpose, compute optimised, memory optimised, storage optimised and accelerated computing.

Choose by workload.

Q6. What is a burstable instance?

Short answer: A T-family instance that accrues CPU credits when idle and uses them to burst.

Sustained load exhausts credits.

Q7. On-Demand versus Reserved versus Spot?

Short answer: On-Demand is flexible, Reserved or Savings Plans trade commitment for discount, and Spot is cheap interruptible capacity.

Mix them in an ASG.

Q8. What is a Spot interruption?

Short answer: AWS reclaims the instance with a two-minute notice.

Handle with checkpoints and diversified pools.

Q9. Savings Plans versus Reserved Instances?

Short answer: Savings Plans commit to hourly spend flexibly across instance types; Reserved Instances commit to specific attributes.

Savings Plans are usually simpler.

Q10. What is an Elastic IP?

Short answer: A static public IPv4 address you own until released and can remap between instances.

Charged as public IPv4.

Q11. How does an instance get AWS permissions?

Short answer: Through an IAM role attached by an instance profile that supplies temporary credentials.

Never store access keys.

Q12. What is IMDSv2?

Short answer: A session-token protected version of the instance metadata service that mitigates SSRF.

Set HttpTokens to required.

Q13. What is user data?

Short answer: A script or cloud-init data run at first boot, up to 16 KB.

Bake an AMI for heavy setup.

Q14. Security group versus NACL?

Short answer: Security groups are stateful and attach to ENIs; NACLs are stateless and attach to subnets.

Use both.

Q15. What is a placement group?

Short answer: A way to influence instance placement: cluster, spread or partition.

Cluster for low latency, spread for isolation.

Q16. What does Auto Scaling do?

Short answer: Maintains and adjusts instance counts across AZs with health replacement and policies.

Pair with an ELB.

Q17. Instance store versus EBS?

Short answer: Instance store is local, fast, ephemeral storage; EBS is durable network-attached storage.

See the EBS course.

Q18. What is hibernation?

Short answer: Saving RAM to the encrypted root volume so the instance resumes with state.

Needs supported types and encryption.

Q19. How do you connect without SSH?

Short answer: Use Systems Manager Session Manager or EC2 Instance Connect.

Needs the SSM agent and IAM role.

Q20. What are Dedicated Hosts?

Short answer: Physical servers dedicated to you for licensing and compliance.

You see sockets and cores.

Q21. What is the Nitro System?

Short answer: AWS's hardware and hypervisor platform offloading networking, storage and security to dedicated hardware.

It gives near bare-metal performance.

Q22. How do you make EC2 highly available?

Short answer: Spread instances across AZs in an Auto Scaling group behind a load balancer and use health checks.

Keep data in durable services.
