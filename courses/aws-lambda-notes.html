AWS Lambda ☁️λ

Serverless compute — run code without managing servers.

1. What is it?

  • Upload code (a function) → AWS runs it when an event happens
  • Pay only for what you use: requests + duration (GB-seconds)
  • Auto-scales (0 → thousands of concurrent runs). No idle cost!
  • AWS handles OS, patching, scaling, availability

2. How it works

Event → Lambda → Your code runs → Result / side-effect

  • Runs inside a lightweight microVM (Firecracker)
  • Handler = entry point, e.g. index.handler
  • Gets event (input JSON) + context (request id, time left…)
def lambda_handler(event, context):
    name = event.get("name", "World")
    return {"statusCode": 200,
            "body": f"Hello {name}!"}

4. Limits to remember ⚠️

  • Timeout: max 15 minutes (900 s)
  • Memory: 128 MB – 10,240 MB (CPU scales with memory)
  • Package: 50 MB zipped (direct) / 250 MB unzipped / container image up to 10 GB
  • /tmp storage: 512 MB (up to 10 GB configurable)
  • Default concurrency: 1,000 per region (soft limit)
  • Payload: 6 MB sync, 256 KB async

5. Cold start vs Warm start

  • Cold start: new environment → download code, start runtime, run init code (slower)
  • Warm start: reuse existing environment (fast)
  • Fix / reduce: Provisioned Concurrency, SnapStart (Java etc.), smaller packages, init outside handler
Tip: put DB connections / SDK clients OUTSIDE the handler so they get reused!

6. Key concepts

  • Execution role (IAM) – what the function is allowed to do
  • Environment variables – config (encrypt secrets with KMS / use Secrets Manager)
  • Layers – shared libs/dependencies across functions
  • Versions & Aliases – immutable snapshots + pointers (prod, dev); weighted traffic shifting
  • Concurrency – Reserved (guarantee + cap) vs Provisioned (pre-warmed)
  • VPC access – attach to subnets to reach RDS etc. (needs NAT for internet)
  • DLQ / Destinations – handle failed async invocations
  • Function URL – built-in HTTPS endpoint, no API Gateway needed

7. Pricing 💰

  • Per request + per ms of duration × memory
  • Free tier: 1M requests + 400,000 GB-s per month
  • More memory = more CPU = often faster → can even be cheaper!

8. Common use cases

  • REST APIs (API Gateway + Lambda + DynamoDB)
  • S3 upload → resize image / process file
  • Scheduled jobs (EventBridge cron)
  • Stream / queue processing (SQS, Kinesis)
  • Chatbots, automation, glue between AWS services

10. Quick CLI

aws lambda create-function --function-name hello \
  --runtime python3.12 --handler app.lambda_handler \
  --role arn:aws:iam::<acct>:role/lambda-role \
  --zip-file fileb://function.zip
aws lambda invoke --function-name hello out.json

Exam memo: Lambda = event-driven + stateless + short-lived. Need state? → DynamoDB / S3 / ElastiCache.
