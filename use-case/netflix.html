High-level architecture

clientedge / protectionservicedata storequeue / streamsolid arrow = sync call · dashed = async event

Simplified from publicly described Netflix architecture.

Playback flow

  1. Player calls the gateway; Playback service checks the plan, region, device and DRM rights.
  2. It picks the best Open Connect servers (closest, healthy, holding the title) and returns a manifest with their URLs.
  3. The player downloads small video chunks directly from the CDN box, not from the cloud.
  4. While playing, the player sends viewing events to Kafka. They feed resume position and recommendations.
4

Deep dive 1: from master file to every screen

  1. Studio uploads a high-quality master to object storage.
  2. Split into chunks (by scene or shot) and encode them in parallel on thousands of workers.
  3. Create a bitrate ladder: many resolutions and bitrates, tuned per title (an animation needs fewer bits than an action film).
  4. Package into DASH / HLS segments, encrypt with DRM.
  5. Push to CDN boxes during off-peak hours, so popular content is already local when evening arrives.
Per-title encoding saves bandwidth with no visible quality loss. At this scale, 10% fewer bits is a very large number.
5

Deep dive 2: adaptive bitrate (ABR)

Networks fluctuate. The player constantly decides which quality to fetch next.

player loop (simplified)
every ~4s chunk:
  throughput = measure(last downloads)
  buffer     = seconds of video already downloaded
  if buffer is low:   pick lower bitrate  (avoid stalls)
  elif throughput is high and buffer is healthy:  pick higher bitrate
  request next chunk at that bitrate from the CDN box
  • Start with a low quality so playback begins in under two seconds, then ramp up.
  • Chunks are small and independent, so switching quality mid-stream is seamless.
  • If an OCA is slow or fails, the player falls over to another URL from the manifest.
6

Deep dive 3: Open Connect CDN

What it isNetflix-owned cache servers placed inside ISP data centres or at internet exchanges.
WhyTraffic stays inside the ISP. The ISP saves transit cost, and the user gets a short, fast path.
Fill strategyPopular titles are pre-loaded overnight. Long-tail titles come from regional hubs.
SteeringPlayback service ranks boxes by health, load, proximity and content availability.
7

Deep dive 4: recommendations and personalisation

  • Offline (batch): Spark jobs train models on viewing history for the whole base.
  • Nearline: events from Kafka update user features within minutes.
  • Online: at request time, rank a pre-computed candidate list using fresh context (time, device).
  • Personalised artwork: the same title can show different posters for different users.
  • Results are cached in EVCache, so the home page loads from memory, not from ML at request time.

Interview cheat-sheet

Why does Netflix run its own CDN?

Video is most of the traffic. Putting cache boxes inside ISPs cuts transit cost, shortens the path, and gives control over quality.

How does playback start so fast?

Start at low bitrate from a nearby CDN box, small chunks, and ramp up as the buffer fills.

What if the recommendation service is down?

Circuit breaker opens, the home page falls back to cached or generic rows. Playback is unaffected.

How do you store viewing history?

Cassandra, partitioned by user and profile with time-ordered rows. Write-heavy, easy to scale, simple resume lookup.
